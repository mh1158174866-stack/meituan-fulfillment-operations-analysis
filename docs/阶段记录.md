### 结果

- 官方仓库提交：`1f9b4288cee5a78d1e5da007fc306bbaa662fc6d`。
- 官方数据下载到 `data/raw/`，解压后约 359 MB；原始目录和本地聚合审计 JSON 均被 Git 忽略。
- 四表共 939,056 行；无空值、无完全重复行。
- 全运单 654,343 行、568,546 个订单、4,955 名骑手；波次 206,748 行；候选骑手 62,044 行；待派订单 15,921 行。
- 关联覆盖率：派单订单→全运单 100%，派单检查点↔候选骑手检查点 100%，波次订单引用→完成运单 100%。
- `dt` 与 Asia/Shanghai 下单日期一致率 99.72%；1,858 条不一致中 1,704 条为预订单。
- 波次起点错误 65,904 条（31.88%），波次终点无差异。
- 参考复核：骑手等权接单率 84.74%，骑手等权配送时长 27.10 分钟，骑手平均配送距离 1.90 km。
- 原始同日波次空闲均值 44.73 分钟；截断至 240 分钟后为 27.44 分钟，复现参考 27.5 分钟。
- 08:00—12:00 需求/容量比在 10 月 21—23 日为 1.03/1.01/1.07，方向复现参考高峰承压结论。
- `validate_stage1.py` 与 `privacy_scan.py` 均通过；24 个 Git 候选文件中无 CSV、ZIP、Parquet 或 DuckDB 原始产物。

### 口径问题

- 公开时间与业务时间必须分开：数据 2024 年公开，业务事件为 2022 年 10 月。
- `dt` 不能直接充当下单日期，尤其是预订单；主分析保留 `dt`、UTC 和 Asia/Shanghai 三套字段。
- 官方 `wave_start_time` 不能直接使用，DWD 层需要从波次订单的最早 `grab_time` 重建。
- 参考空闲时长隐含 240 分钟截断；主项目同时报告原始口径和复核口径。
- 参考报告的坐标缩放文字与示例矛盾；示例和距离 KPI 均支持除以 `1e6`。
- 参考报告未公开 `recipient_area` 构造规则，且官方说明 `da_id` 并非纯地理分区，因此专区/多区域结果不判定通过。
- 高峰容量公式是根据报告叙述推断的离线代理，不是官方线上产能定义。

### 验收结论

通过，带一项未决口径：专区/多区域骑手分组待项目自行建立透明定义。其余数据来源、文件质量、时间、主键、关联、事件顺序、核心 KPI 与高峰方向均通过，可进入 DWD 清洗和核心经营分析。

## 阶段 2：轻量分析数据与指标体系（2026-09-03）

### 目标

不建设复杂企业数仓，将阶段一已验证的口径落为少量、透明、可审计的 DuckDB 明细和聚合对象，为后续经营分析提供稳定输入。

### 主命令

```bash
.venv/bin/python -m pip install duckdb==1.4.1
PYTHON_BIN=.venv/bin/python scripts/run_stage2.sh
.venv/bin/python scripts/validate_stage2.py
.venv/bin/python scripts/privacy_scan.py
git diff --check
git status --short --branch
```

`scripts/run_stage2.sh` 内部执行两次全量重建、两次结构/指标校验、一次语义指纹比较和一次 Git 隐私扫描。

### 数据对象与实际规模

- `dwd_waybill`：654,343 行，一行一运单。
- `dwd_order_wave_bridge`：568,545 行，一行一个波次内订单引用。
- `dwd_courier_wave`：206,748 行，一行一个骑手波次。
- `ads_operations_overview`：13 行，一行一个 Asia/Shanghai 平台下单日。
- `ads_hourly_supply_demand`：223 行，一行一个 Asia/Shanghai 平台下单小时。
- `dws_courier_efficiency`：4,955 行，一行一名骑手的全期聚合。
- `ads_anomaly_diagnosis`：11 行，一行一种异常类型。

### 口径结果

- 85,797 条拒绝运单、568,545 条完成运单和 1 条已接受未完成运单已明确分开。
- 运单加权接单率 86.8881%；骑手等权接单率 84.7436%。
- 完成运单平均配送时长 25.72 分钟；平均全链路时长 35.49 分钟；超时率 15.0081%。
- 65,904 个波次起点经由波次内最早 `grab_time` 修正，原值、绝对误差和差异标记均保留；波次终点差异为 0。
- 修正波次平均时长 37.18 分钟，平均负载 2.75 单；177,825 个同日非负空闲间隔均值 43.11 分钟。
- 分时运力是修正波次与小时时间窗重叠的去重骑手数；容量代理为 `online_couriers * 60 / avg_delivery_minutes`。

### 验收与问题

- 7 张核心表的行数、主键、订单—波次覆盖、波次首尾、运单状态和聚合总数回勾均通过。
- 首次使用 4 线程聚合时，浮点归并顺序使三张聚合表的语义哈希不稳定。改为单线程构建后，两次全量重建的 7 张表结构、行数和全表语义哈希完全一致。
- 隐私扫描通过：40 个 Git 候选文件中没有 CSV、ZIP、Parquet、DuckDB、PDF 数据附件或明细级数据目录内容。
- 专区/多区域骑手口径仍未构造；小时容量只能称为离线代理。

### 验收结论
