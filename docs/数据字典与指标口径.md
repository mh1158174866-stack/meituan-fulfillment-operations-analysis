# 数据字典与指标口径

## 原则

- 先固定订单、运单、骑手和波次粒度，再计算 KPI。
- 以业务时间戳重建分析日期；`dt` 仅作为原始分区日期保留。
- 所有时长保留起止节点、单位、过滤条件和有效样本量。
- 明细 ID 只保存于 Git 忽略的本地分析库，公开产物仅使用聚合结果。

## 第二阶段核心数据对象

| 对象 | 粒度/主键 | 行数 | 用途 |
|---|---|---:|---|
| `dwd_waybill` | `waybill_id` | 654,343 | 运单状态、UTC/上海时间、时长、距离和异常标记 |
| `dwd_order_wave_bridge` | `(dt, courier_id, wave_id, order_id)` | 568,545 | 解析波次订单集合并连接完成运单 |
| `dwd_courier_wave` | `(dt, courier_id, wave_id)` | 206,748 | 修正波次起点、负载、波次时长、空闲时长和容量代理 |
| `ads_operations_overview` | `business_date_cn` | 13 | 按平台下单日的经营总览 |
| `ads_hourly_supply_demand` | `business_hour_cn` | 223 | 分时需求、在线骑手和容量代理 |
| `dws_courier_efficiency` | `courier_id` | 4,955 | 骑手全期接单、配送、距离、波次和空闲聚合 |
| `ads_anomaly_diagnosis` | `anomaly_type` | 11 | 异常计数、分母、比例与阈值 |

ODS 是运行期临时只读视图，直接映射官方 CSV，不作为持久化核心对象。上述明细对象包含原始 ID，只保存于 `data/processed/meituan_fulfillment.duckdb`。

## 运单状态口径

| 状态 | 条件 | 实际行数 |
|---|---|---:|
| `rejected` | `is_courier_grabbed=0` | 85,797 |
| `accepted_unfinished` | `is_courier_grabbed=1 AND arrive_time=0` | 1 |
| `completed` | `is_courier_grabbed=1 AND arrive_time>0` | 568,545 |

接单率以运单为分母，因为拒单后会产生新运单；完成率以去重订单为分母。不将 654,343 条运单误写为订单量。

## 时间口径

数据公开时间为 2024 年，业务发生时间为 2022 年 10 月。项目保留：

- `dt`：原始分区/日期字段，不改写；
- `*_epoch`：原始 Unix 秒；
- `*_utc`：UTC 事件时间；
- `*_cn`：Asia/Shanghai 业务时间；
- `business_date_cn`：由 `platform_order_time` 构造的需求日期；
- `service_request_date_cn`：由 `order_push_time` 构造的履约请求日期。

`dt` 与 `business_date_cn` 不一致 1,858 条，主要为提前创建的预订单。分时需求仍按 `platform_order_time` 的 Asia/Shanghai 小时归属，表中单独保留 `prebook_order_count`；不用单一日期覆盖需求创建和履约事件。

## 数据粒度与主键

- 全运单：`waybill_id` 唯一；一个 `order_id` 可对应多个运单。
- 骑手波次：`(dt, courier_id, wave_id)` 唯一。
- 订单—波次桥：`(dt, courier_id, wave_id, order_id)` 唯一，只关联完成运单。
- 待派订单：`(dt, dispatch_time, order_id)` 唯一。
- 候选骑手：`(dt, dispatch_time, courier_id)` 唯一。

## 波次修正

`wave_start_time` 存在官方确认的索引问题。DWD 层新增 `wave_start_time_corrected=min(grab_time)`、`wave_start_mismatch_flag` 和误差秒数；原字段只读保留。65,904/206,748 个波次起点存在差异。`wave_end_time` 已验证等于波次内最晚送达时间，差异为 0。

## 已固定指标

| 指标 | 公式、分母与过滤 | 有效样本/实算校验 |
|---|---|---|
| 运单加权接单率 | `accepted waybills / assigned waybills` | 568,546 / 654,343 = 86.8881% |
| 骑手等权接单率 | 每名骑手先算接单率，再对骑手等权平均 | 4,955 名骑手，84.7436% |
| 订单完成率 | 完成订单数 / 去重订单数 | 568,545 / 568,546 |
| 配送时长 | `(arrive_time - grab_time) / 60`；仅 `completed` | 568,545 条；运单加权均值 25.72 分钟；4,901 名完成骑手等权均值 27.10 分钟 |
| 全链路时长 | `(arrive_time - platform_order_time) / 60`；仅 `completed` | 568,545 条；均值 35.49 分钟 |
| 配送距离 | 发货地到收货地 Haversine；坐标整数先除以 `1e6`；仅 `completed` | 568,545 条；运单加权均值 1.61 km；骑手等权均值 1.90 km |
| 超时率 | `arrive_time > estimate_arrived_time`；分母为完成运单 | 85,328 / 568,545 = 15.0081% |
| 修正波次时长 | `(wave_end_time - min(grab_time in wave)) / 60` | 206,748 个波次；均值 37.18 分钟 |
| 波次负载 | 波次内关联的完成订单数 | 206,748 个波次；均值 2.75 单，最大 59 单 |
| 空闲时长 | 同骑手、同 `dt` 下，下一修正波次起点减当前波次结束；主口径只保留非负间隔 | 177,825 个；均值 43.11 分钟；无负间隔 |
| 240 分钟空闲复核口径 | 主口径上额外保留 `idle<=240` | 169,629 个；均值 26.08 分钟；仅为条件复核 |
| 小时在线骑手 | 修正波次时间区间与当前小时重叠的去重骑手数 | 223 个小时中 193 个有在线骑手 |
| 小时容量代理 | `online_couriers * 60 / avg_delivery_minutes` | 192 个小时同时有运力与有效配送时长 |
| 需求/容量比 | `order_count / capacity_orders_proxy` | 离线容量代理，不是官方产能或因果效果 |

## 未纳入口径

- 跨区率和专区/多区域骑手仍不纳入：参考报告未公开 `recipient_area` 构造，`da_id` 不是可直接当作纯地理收货区的字段。
- 小时容量代理只用于后续经营诊断，不表示可调度骑手、真实平台产能或 A/B Test 效果。
- 本阶段不输出区域策略、正式看板、预测模型或业务效果结论。
